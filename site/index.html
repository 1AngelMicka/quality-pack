Plugins pour Claude Code

Coder proprement dès le départ, puis le prouver.

quality-pack donne à Claude des règles précises pendant qu’il code, puis audite le projet et lui donne une note sur 10, domaine par domaine. Chaque critère exige une preuve. Le tout en dépensant le moins de tokens possible.

  • 28 domaines
  • 226 critères vérifiables
  • 0 télémétrie

Le principe

Un assistant de code produit vite quelque chose qui marche à peu près. Il oublie souvent les écrans vides, la validation côté serveur, l’accessibilité, le RGPD ou les sauvegardes, et il a tendance à produire des interfaces et des textes génériques. quality-pack corrige ça en deux temps : des règles pendant la construction, puis un audit qui exige une preuve pour chaque point.

/qp:kickoff

Claude lit le projet, pose quelques questions et écrit sa fiche qualité.

tu codes

Les règles des domaines touchés s’appliquent toutes seules.

/qp:audit

Scans automatiques puis auditeurs en parallèle : note, preuves, priorités.

/qp:fix

Les problèmes sont corrigés dans l’ordre, bloquants d’abord.

/qp:handoff

Une note courte pour reprendre la tâche à la session suivante.

Installation

Il te faut Claude Code, Node.js 18 ou plus récent, et git. Les commandes /plugin se tapent dans Claude Code (terminal ou application de bureau).

  1. Ajoute la marketplace et installe le plugin principal. 
    /plugin marketplace add 1AngelMicka/quality-pack
/plugin install qp@quality-pack
  2. Installe les modules de ta techno (seulement ceux que tu utilises). 
    # Next.js, React, TypeScript, Tailwind
/plugin install qp-nextjs@quality-pack
# Fastify ou Express, Prisma, PostgreSQL, Redis, Socket.io
/plugin install qp-node-api@quality-pack
# Serveur auto-hébergé : Docker Compose, PM2, Nginx ou CloudPanel
/plugin install qp-vps@quality-pack
# App mobile Expo ou React Native
/plugin install qp-expo@quality-pack
# Webapp livrée en app mobile avec Capacitor
/plugin install qp-capacitor@quality-pack
  3. Redémarre Claude Code (ou tape /reload-plugins), ouvre ton projet et lance : 
    /qp:kickoff
  4. Tâches clés et vérifications navigateur, une fois pour toutes (Claude te le propose au premier audit) : 
    node <dossier du plugin>/scripts/qp.mjs browser-setup
    Playwright, axe-core et Chromium vont dans le cache du pack, pas dans ton projet. Sans eux, l’audit fonctionne ; ces critères sont marqués « non vérifiés ».
  5. Facultatif : Graphify pour économiser des tokens sur les projets moyens et gros. /qp:kickoff te le propose quand c’est utile.

Pour toute une équipe

Dans le dossier du projet, une seule fois dans le terminal, puis commite .claude/settings.json :

claude plugin marketplace add 1AngelMicka/quality-pack --scope project
claude plugin install qp@quality-pack --scope project

Mettre à jour, désinstaller

# mettre à jour
/plugin marketplace update quality-pack
# désinstaller
/plugin uninstall qp@quality-pack
/plugin marketplace remove quality-pack

Pour les mises à jour automatiques : /plugin → Marketplaces → quality-pack → Enable auto-update.

Économie de tokens

Le pack réduit trois choses : ce qui est chargé en permanence, ce que Claude lit, et ce qui est refait d’une fois sur l’autre.

MécanismeEffet
Règles à la demandeEnviron 1 150 tokens chargés par session. Le détail des règles ne se charge que quand Claude touche le domaine.
Scans en scriptsRemplissage, formules creuses, logs oubliés, en-têtes, SEO et navigateur tournent en Node. Claude lit un résumé.
Sorties compactesTests, lint et audits gardent leur log complet sur le disque ; Claude ne lit que les erreurs. Sur notre test : 3 000 lignes, environ 14 700 tokens ramenés à environ 190.
Audit incrémentalSeuls les critères que les fichiers modifiés peuvent affecter sont revérifiés. Rien n’a changé : aucun auditeur lancé.
Mode rapide/qp:audit quick : sans agents auditeurs.
Modèle des auditeursOpus (recommandé) ou Fable : les petits modèles ont donné de fausses preuves lors d’audits réels. L’économie vient des audits incrémentaux et des sorties compactes.
Passage de relais/qp:handoff évite de réexplorer le projet à chaque nouvelle session.

Notation

  • Chaque critère est bloquant (5 points), majeur (3) ou mineur (1). Réussi : tous les points ; partiel : la moitié ; en échec ou non vérifié : aucun.
  • Un critère réussi sans preuve compte comme non vérifié.
  • Deux notes : Expérience (produit, parcours, ergonomie, interface, accessibilité, vitesse) et Technique et exploitation (sécurité, données, code, tests, intégrations, serveur, sauvegardes).
  • Un point bloquant en échec plafonne son domaine à 3/10 et la note dont il relève à 5,9/10, pas l’autre.
  • Chaque note pondère ses domaines selon le type de projet : vitrine, application web, SaaS, mobile ou API. Les domaines sans objet sont ignorés. La note d’ensemble reste dans le rapport pour l’historique.
  • Les tâches clés sont jouées sur téléphone et ordinateur : l’interface est jugée sur ces états, pas sur l’écran vide. Une revue d’ergonomie et une contre-vérification complètent les auditeurs.

Pour les agents IA

Tu peux confier l’installation à ton assistant IA : donne-lui simplement le lien du repo. Il trouvera llms.txt et le guide écrit pour les agents, qui décrit chaque étape, les vérifications et les erreurs courantes.

En cas de problème

ProblèmeSolution
« /plugin isn’t available in this environment »Les commandes /plugin se tapent dans Claude Code (terminal ou application de bureau), pas dans une conversation web.
Les commandes /qp:… n’apparaissent pasRedémarre Claude Code ou tape /reload-plugins, puis regarde /plugin → Installed et l’onglet Errors.
node: command not foundInstalle Node.js 18+ et vérifie que node est dans le PATH.
L’ajout de la marketplace échoueVérifie git. Sans clé SSH GitHub : CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1, puis réessaie.
Vérifications navigateur « non vérifiées »Lance qp.mjs browser-setup, lance l’appli en local ou renseigne une URL de préproduction.
Écriture bloquée comme secretMets la valeur dans une variable d’environnement. Si ce n’est pas un secret : commentaire qp-allow-secret sur la ligne.
L’audit incrémental refait toutNormal au premier audit, après une mise à jour du pack, après 30 jours, ou hors d’un dépôt Git.

Le pack n’envoie aucune télémétrie et ne contacte que les URL de ton projet pendant un audit. Il aide à repérer les obligations légales, mais il ne remplace pas l’avis d’un juriste.
