Plugins for Claude Code

Build it properly from the start, then prove it.

quality-pack gives Claude precise rules while it codes, then audits the project and scores it out of 10, domain by domain. Every check needs evidence. All while spending as few tokens as possible.

  • 28 domains
  • 162 verifiable checks
  • 0 telemetry
  • EN · FR · MIT

How it works

A coding assistant quickly produces something that roughly works. It often forgets empty states, server-side validation, accessibility, privacy or backups, and it tends to produce generic interfaces and copy. quality-pack fixes that in two steps: rules while building, then an audit that needs evidence for every point.

/qp:kickoff

Claude reads the project, asks a few questions and writes its quality profile.

you code

The rules of the domains you touch apply automatically.

/qp:audit

Automatic scans, then auditors in parallel: score, evidence, priorities.

/qp:fix

Issues are fixed in order, blockers first.

/qp:handoff

A short note to resume the task in the next session.

Install

You need Claude Code, Node.js 18 or later, and git. Type /plugin commands in Claude Code (terminal or desktop app).

  1. Add the marketplace and install the core plugin. 
    /plugin marketplace add 1AngelMicka/quality-pack
/plugin install qp@quality-pack
  2. Install the modules for your stack (only those you use). 
    # Next.js, React, TypeScript, Tailwind
/plugin install qp-nextjs@quality-pack
# Fastify or Express, Prisma, PostgreSQL, Redis, Socket.io
/plugin install qp-node-api@quality-pack
# Self-hosted server: Docker Compose, PM2, Nginx or CloudPanel
/plugin install qp-vps@quality-pack
  3. Restart Claude Code (or run /reload-plugins), open your project and run: 
    /qp:kickoff
  4. Optional: browser and accessibility checks. In your project: 
    node <plugin folder>/scripts/qp.mjs browser-setup
    Without them the audit still runs; those checks are marked "not checked".
  5. Optional: Graphify to save tokens on medium and large projects. /qp:kickoff suggests it when it helps.

For a whole team

In the project folder, run once in the terminal, then commit .claude/settings.json:

claude plugin marketplace add 1AngelMicka/quality-pack --scope project
claude plugin install qp@quality-pack --scope project

Update, uninstall

# update
/plugin marketplace update quality-pack
# uninstall
/plugin uninstall qp@quality-pack
/plugin marketplace remove quality-pack

For automatic updates: /plugin → Marketplaces → quality-pack → Enable auto-update.

Token economy

The pack cuts three things: what is always loaded, what Claude reads, and what is redone from one time to the next.

MechanismEffect
Rules on demandAbout 1,150 tokens loaded per session. Detailed rules load only when Claude touches that domain.
Scans as scriptsFiller text, hollow wording, leftover logs, headers, SEO and browser checks run in Node. Claude reads a summary.
Compact outputsTests, lint and audits keep their full log on disk; Claude only reads the errors. In our test: 3,000 lines, about 14,700 tokens down to about 190.
Incremental auditOnly criteria that changed files can affect are checked again. Nothing changed: no auditor runs.
Quick mode/qp:audit quick: no auditor agents.
Auditor modelOpus (recommended) or Fable: smaller models gave wrong evidence in real audits. Savings come from incremental audits and compact outputs.
Handoff/qp:handoff avoids exploring the project again in every new session.

Scoring

  • Each check is a blocker (5 points), major (3) or minor (1). Passed: all points; partial: half; failed or not checked: none.
  • A check passed without evidence counts as not checked.
  • Two scores: Experience (product, flows, ergonomics, interface, accessibility, speed) and Engineering and operations (security, data, code, tests, integrations, server, backups).
  • A failed blocker caps its domain at 3/10 and the score it belongs to at 5.9/10, not the other one.
  • Each score weights its domains by project type: showcase site, web app, SaaS, mobile or API. Domains that do not apply are skipped. The overall score stays in the report for history.
  • Key tasks are played on a phone and a desktop: the interface is judged on those states, not on the empty screen. An ergonomics review and a counter-check complete the auditors.

For AI agents

You can hand the install over to your AI assistant: just give it the repository link. It will find llms.txt and the guide written for agents, which covers each step, the checks and the common errors.

Install and set up quality-pack for this project by following
https://github.com/1AngelMicka/quality-pack/blob/main/docs/AGENT_GUIDE.md

Files created in your project

.quality/
  project.json          project profile (/qp:kickoff)
  AUDIT.md              latest audit report
  audits/<date>.json    every audit, to follow the score
  audits/<date>/logs/   full command outputs
  fixes.md              fix log (/qp:fix)
  handoff.md            handoff between sessions (/qp:handoff)
DESIGN.md               visual direction and design tokens
CLAUDE.md               a short "Quality pack" section

Commit .quality/ to keep the history; screenshots and logs are git-ignored.

Troubleshooting

ProblemFix
"/plugin isn't available in this environment"Type /plugin commands in Claude Code (terminal or desktop app), not in a web chat.
/qp:… commands do not appearRestart Claude Code or run /reload-plugins, then check /plugin → Installed and the Errors tab.
node: command not foundInstall Node.js 18+ and make sure node is on your PATH.
Adding the marketplace failsCheck git. Without a GitHub SSH key: CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1, then retry.
Browser checks "not checked"Run qp.mjs browser-setup, run the app locally or set a staging URL.
A write is blocked as a secretMove the value to an environment variable. If it is not a secret: comment qp-allow-secret on that line.
The incremental audit redoes everythingIntended on the first audit, after a pack update, after 30 days, or outside a Git repository.

The pack sends no telemetry and only contacts your project's URLs during an audit. It helps you spot legal obligations; it is not legal advice.
