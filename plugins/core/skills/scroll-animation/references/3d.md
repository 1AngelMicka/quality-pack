# Interactive 3D

For a 3D object or scene in a page: a product the visitor turns, a hero scene, a scene that follows the scroll. Versions and licences checked on 2026-11-13: three.js 0.187 (MIT), React Three Fiber 9.8 (MIT, needs React 19; use v8 with React 18), drei 10.7 (MIT), model-viewer 4.4 (Apache-2.0), glTF Transform 4.5 (MIT).

3D is the most expensive thing a page can carry: a large download, a GPU that phones share with everything else, and content that search engines, screen readers and keyboards cannot reach. So the first question is whether a video, an image sequence or a picture would say the same thing. Keep 3D when the visitor gains something by handling the object (turn it, open it, configure it) or when the scene is the subject of the page.

## 1. Pick the tool

| Need | Tool | Why |
| --- | --- | --- |
| Show one model, let the visitor turn it | [`<model-viewer>`](https://modelviewer.dev) | one HTML tag; poster, lazy loading, `alt`, keyboard rotation and `touch-action` are built in |
| A custom scene in a React project | [React Three Fiber](https://github.com/pmndrs/react-three-fiber) + [drei](https://github.com/pmndrs/drei) | the scene is components; drei brings controls, loaders, environment, performance helpers |
| A custom scene without React (Vue, Svelte, Astro, plain HTML) | [three.js](https://threejs.org) directly | no wrapper to keep in step |
| The scene follows the page scroll | three.js or R3F, driven by a scroll progress value (section 5) | native scrolling is kept |

## 2. The four rules, applied to 3D

1. **A picture first, the canvas second.** The page ships a poster image (a render of the scene) in the HTML. The 3D code loads later, only when the block is near the viewport, and replaces the poster once the first frame is drawn. The poster stays when WebGL is missing, when the context is lost, on data saver, and with JavaScript off. The largest content the page paints first is the poster, never the canvas.
2. **Nothing to read lives only in the canvas.** Titles, prices, labels and buttons are HTML above or beside it. The canvas has `role="img"` and an `aria-label` that says what is shown, or `aria-hidden="true"` when it is decoration.
3. **The page still scrolls over the canvas.** No zoom on the wheel, no vertical drag captured on phones: `touch-action: pan-y` on the canvas, rotation on horizontal drag only.
4. **Motion the visitor did not start is optional.** With reduced motion: no auto-rotation, no camera travel tied to scroll, no floating; the scene shows its final pose. Rotation by dragging stays, since the visitor asked for it.

## 3. Recipes

### One model: model-viewer

```html
<script type="module" src="/vendor/model-viewer.min.js"></script>
<model-viewer src="/models/chair.glb" poster="/models/chair.webp" alt="Oak chair with a woven seat, seen from the front left"
  loading="lazy" reveal="auto" camera-controls disable-zoom touch-action="pan-y" interaction-prompt="none"
  style="width: 100%; aspect-ratio: 4 / 3"></model-viewer>
```

`disable-zoom` leaves the wheel to the page. Add `auto-rotate` only inside a reduced-motion check (set the attribute from JavaScript when `matchMedia("(prefers-reduced-motion: no-preference)").matches`).

### A scene in React: React Three Fiber

```jsx
// Scene.jsx — loaded on demand, never in the first bundle (Next.js: dynamic(() => import("./Scene"), { ssr: false }))
"use client";
import { Suspense } from "react";
import { Canvas } from "@react-three/fiber";
import { useGLTF, PresentationControls, Environment, ContactShadows, AdaptiveDpr } from "@react-three/drei";

function Model() {
  const { scene } = useGLTF("/models/chair.glb");
  return <primitive object={scene} />;
}

export default function Scene() {
  return (
    <Canvas frameloop="demand" dpr={[1, 2]} camera={{ position: [0, 0.6, 3], fov: 35 }}
      role="img" aria-label="Oak chair with a woven seat" style={{ touchAction: "pan-y" }}>
      <Suspense fallback={null}>
        <PresentationControls polar={[-0.2, 0.3]} azimuth={[-Infinity, Infinity]}>
          <Model />
        </PresentationControls>
        <Environment files="/hdri/studio_1k.hdr" />
        <ContactShadows position={[0, -0.5, 0]} opacity={0.4} blur={2} />
      </Suspense>
      <AdaptiveDpr pixelated />
    </Canvas>
  );
}
```

- `frameloop="demand"` draws a frame only when something changed: drei's controls ask for one while the visitor drags; your own changes call `invalidate()` (from `useThree`). A scene left on the default loop draws 60 or 120 frames a second for nothing and drains phone batteries.
- `PresentationControls` turns the object on drag and does not take the wheel. `OrbitControls` sets `touch-action: none` on the canvas, which blocks page scrolling on phones: if you need it, set `enableZoom={false}` and `enablePan={false}` and put the canvas in a block the thumb can scroll around.
- Host the environment file yourself: drei's `preset="…"` environments are fetched from a third-party CDN and are meant for prototypes.
- Animate in `useFrame((state, delta) => …)` by changing refs, never React state, and multiply by `delta` so the speed does not depend on the screen's refresh rate.

### A scene without React: three.js

```js
import * as THREE from "three";
import { GLTFLoader } from "three/addons/loaders/GLTFLoader.js";

export async function mount(canvas) {
  const renderer = new THREE.WebGLRenderer({ canvas, antialias: true, alpha: true });
  renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
  const scene = new THREE.Scene();
  const camera = new THREE.PerspectiveCamera(35, 1, 0.1, 50);
  camera.position.set(0, 0.6, 3);
  scene.add(new THREE.HemisphereLight(0xffffff, 0x445566, 2));
  const { scene: model } = await new GLTFLoader().loadAsync("/models/chair.glb");
  scene.add(model);

  const render = () => renderer.render(scene, camera);
  new ResizeObserver(() => {
    const { clientWidth: w, clientHeight: h } = canvas;
    renderer.setSize(w, h, false); camera.aspect = w / h; camera.updateProjectionMatrix(); render();
  }).observe(canvas);

  // Horizontal drag turns the model; vertical drag still scrolls the page (canvas has touch-action: pan-y).
  let last = null;
  canvas.addEventListener("pointerdown", (e) => { last = e.clientX; canvas.setPointerCapture(e.pointerId); });
  canvas.addEventListener("pointermove", (e) => { if (last === null) return; model.rotation.y += (e.clientX - last) * 0.01; last = e.clientX; render(); });
  canvas.addEventListener("pointerup", () => { last = null; });
  // The same with the keyboard (give the canvas tabindex="0") and with two visible buttons.
  canvas.addEventListener("keydown", (e) => { const d = { ArrowLeft: -0.2, ArrowRight: 0.2 }[e.key]; if (d) { model.rotation.y += d; render(); } });

  canvas.addEventListener("webglcontextlost", (e) => { e.preventDefault(); canvas.hidden = true; });   // the poster behind shows again
  return () => { scene.traverse((o) => { o.geometry?.dispose(); [o.material].flat().forEach((m) => { m?.map?.dispose(); m?.dispose(); }); }); renderer.dispose(); };
}
```

Call the returned function when the block leaves the page (route change in a single-page app): three.js does not free GPU memory by itself.

### Load late, stop when unseen

```js
const block = document.querySelector(".scene");
const start = new IntersectionObserver(async ([e]) => {
  if (!e.isIntersecting) return;
  start.disconnect();
  if (navigator.connection?.saveData) return;                       // the poster stays
  const { mount } = await import("./scene.js");
  await mount(block.querySelector("canvas"));
  block.classList.add("is-live");                                   // CSS fades the poster out
}, { rootMargin: "300px" });
start.observe(block);
```

A scene with a running loop (auto-rotation, particles) stops it when the canvas is off-screen or the tab is hidden: `renderer.setAnimationLoop(visible && !document.hidden ? tick : null)`, from an IntersectionObserver and `visibilitychange`. In R3F, switch `frameloop` between `"always"` and `"never"` the same way.

## 4. Models and textures

- Format: glTF binary (`.glb`). Convert anything else in Blender (free, GPL: the tool, not your export).
- Compress before shipping, with [glTF Transform](https://gltf-transform.dev) (MIT):

```bash
npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress webp --texture-size 1024
```

  Meshopt needs `loader.setMeshoptDecoder(MeshoptDecoder)` (from `three/addons/libs/meshopt_decoder.module.js`); drei's `useGLTF` sets it up by itself. Draco compresses geometry more but its decoder is a separate download: host it yourself, do not load it from a third-party CDN.
- `npx gltfjsx model.glb --transform` writes a React component from a model. Useful, but the tool has had no release since 2024: read what it generates.
- Lighting: one small environment map (1k HDR or less) does more than several lights. Real-time shadows are costly: prefer baked shadows or drei's `ContactShadows`.
- Free models with a licence you can check: [Poly Haven](https://polyhaven.com) (CC0, also HDR environments and textures), [Khronos glTF Sample Assets](https://github.com/KhronosGroup/glTF-Sample-Assets) (each model has its own licence file: read it). On marketplaces, every model has its own licence; many forbid redistribution. Record each model in the project's asset list with its licence and author.

## 5. Tie the scene to the scroll

Keep native scrolling: read where the section is, and set the scene from that value. With reduced motion, skip this and render the final pose once.

```js
// plain three.js — the section is a tall block with the canvas sticky inside it
const progress = () => { const b = section.getBoundingClientRect(); return Math.min(1, Math.max(0, -b.top / (b.height - innerHeight))); };
let queued = false;
addEventListener("scroll", () => {
  if (queued) return; queued = true;
  requestAnimationFrame(() => { queued = false; const p = progress(); model.rotation.y = p * Math.PI * 2; camera.position.z = 3 - p; render(); });
}, { passive: true });
```

```jsx
// React Three Fiber with Motion: useScroll gives the progress of the section, the frame is drawn on change
const { scrollYProgress } = useScroll({ target: sectionRef, offset: ["start start", "end end"] });
const invalidate = useThree((s) => s.invalidate);
useMotionValueEvent(scrollYProgress, "change", (p) => { group.current.rotation.y = p * Math.PI * 2; invalidate(); });
```

GSAP ScrollTrigger does the same with `scrub: true` and an `onUpdate` that sets the scene and renders. drei's `ScrollControls` replaces the page scroll with its own scroller inside the canvas: anchors, find-in-page and the content outside the canvas stop working with it, so keep it for a page that is only the scene. r3f-scroll-rig keeps the page scroll but has had no release since 2025.

## 6. Budgets

No standard sets these numbers. They are working limits for a mid-range phone, drawn from the React Three Fiber and three.js performance guides; measure on a real phone before raising them.

| What | Limit | How to read it |
| --- | --- | --- |
| Model files for the first scene | 2 MB compressed | network panel |
| JavaScript for 3D | loaded on demand, outside the first bundle | bundle report |
| Textures | 1024 px on phones, 2048 px at most | `gltf-transform inspect` |
| Draw calls per frame | under 100 | `renderer.info.render.calls` |
| Triangles per frame | under 200 000 | `renderer.info.render.triangles` |
| Pixel ratio | capped at 2 (drei `AdaptiveDpr` or `PerformanceMonitor` lowers it under load) | `renderer.getPixelRatio()` |
| Frames while nothing moves | 0 | the count in `renderer.info.render.frame` stays still |

Many copies of one object: one `InstancedMesh` (drei `Instances`), not many meshes. Post-processing (bloom, depth of field) doubles the cost on phones: leave it out there.

## 7. Prove it

1. JavaScript off, then reduced motion on: the poster and all the text are there; nothing turns by itself.
2. `sw.mjs look <url> --mode <surface>`: `scroll_hijack`, `content_without_animation` and `reduced_motion` pass. It does not look inside the canvas: the rest is checked by hand.
3. On a phone, or with the browser's device mode and CPU throttling ×4: drag the page vertically starting on the canvas (it scrolls), drag horizontally (the model turns), and read the numbers of section 6 in the console.
4. With the keyboard: Tab reaches the canvas or its buttons, the arrows turn the model, Tab leaves it. Wheel over the canvas scrolls the page.
5. Leave the tab idle for a minute: the frame count does not move.

## Rules

| ID | Rule | Threshold | Source |
| --- | --- | --- | --- |
| 3D-01 | Poster before canvas | an image is in the HTML and stays without WebGL, without JavaScript and on data saver | progressive enhancement; web.dev LCP guidance |
| 3D-02 | Text alternative | canvas has `role="img"` + a label, or `aria-hidden`; no information only in the canvas | WCAG 1.1.1 |
| 3D-03 | Keyboard and no-drag alternative | rotation works with keys or buttons | WCAG 2.1.1, 2.5.7 |
| 3D-04 | Page scroll kept over the canvas | wheel and vertical touch drag scroll the page | NN/g "Scrolljacking 101" (2023) |
| 3D-05 | Reduced motion | no auto-rotation, no scroll-driven camera | WCAG 2.3.3 |
| 3D-06 | Render on demand | 0 frames drawn when nothing moves, off-screen or in a hidden tab | React Three Fiber "Scaling performance" |
| 3D-07 | Loaded on demand | 3D code and models are outside the first load | web.dev code splitting |
| 3D-08 | Memory freed | geometries, materials, textures and the renderer are disposed on unmount | three.js manual "How to dispose of objects" |
| 3D-09 | Every model has a recorded licence | author and licence in the asset list | this pack's sourcing rule |
