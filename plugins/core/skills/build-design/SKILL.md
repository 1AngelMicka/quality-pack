# Design and accessibility: build rules

Apply these rules while you build. Domains or criteria whose `applies_if` flags are false in `.quality/project.json` do not apply to this project. Before you call a task done, check your work against the criteria of the domains you touched: each one must be true and verifiable.

If a stack module of Shipwright is installed (sw-nextjs, sw-node-api, sw-vps, sw-expo, sw-capacitor, sw-tauri, sw-electron), its rules skill adds stack-specific rules on top of these.

## UI (UI)

Visual consistency, alignment and interactive states.

Applies when: The project has a user interface.

Rules:

- Define tokens (colours, type, spacing, radius, shadows) before screens, and use only them.
- One spacing scale (e.g. 4 or 8 px); no arbitrary spacing.
- Every interactive element has its states: rest, hover, visible focus, active, disabled, loading.
- One icon library and at most two font families.

Done means:

- [major] UI-01: Colours, sizes and spacing go through tokens. Check: Search for hard-coded values (hex, arbitrary px, arbitrary Tailwind classes) in components.
- [major] UI-02: All interactive elements have hover, visible focus, active and disabled. Check: Go through buttons, links and fields with keyboard and mouse.
- [major] UI-03: Consistent alignment and grid, nothing overflowing. Check: deslop.json: no high finding (inverted proximity, uneven gaps, drifting edges, cramped text, overflow) at the three widths, a few med at most; screenshots: equal left and right edges, no clipped text.
- [minor] UI-04: Clear and limited type hierarchy. Check: At most 2 font families and a defined size scale; look.json: checks.font_sizes, font_families, line_length and line_height.
- [minor] UI-05: Components reused rather than duplicated with variations. Check: Search for buttons, cards, modals implemented several times.
- [minor] UI-06: Dark mode is complete and readable (only if: dark_mode). Check: No component left light, contrast checked in both themes.

## AI slop (SLP)

Removal of generic content, robotic jargon and useless visuals.

Applies when: The project has a user interface.

Rules:

- Pick a project-specific visual direction at /kickoff (references, mood, constraints), never a default style.
- No default purple gradient, glass cards everywhere, emoji as icons, generic three-column 'Why choose us' sections.
- Ban hollow wording: 'revolutionary', 'effortless', 'unlock your potential', 'dive into', 'seamless', 'elevate'.
- Every visual shows the real product, a real place or real data; otherwise it is removed.
- Animations serve understanding or feedback, never decoration alone.

Done means:

- [major] SLP-01: No hollow phrase or AI jargon in the copy. Check: Scan the copy with the pack's FR/EN blacklist; reread headings and taglines.
- [major] SLP-02: The visual direction is project-specific and documented. Check: DESIGN.md states the choices (mood, colours, type) and they show on screen; compare with default templates (raw shadcn, purple gradient, glass). DESIGN.md existing is not enough; following how the references are organised is checked by ERG-08.
- [major] SLP-03: No decorative visual without information (generic illustrations, blobs, random icons). Check: For each image or illustration: what real thing does it show?
- [minor] SLP-04: Sections answer a user question, not a template. Check: Look for generic blocks: invented testimonials, 'Our values', grids of 3 vague benefits; look.json: tier "strong" in persuade mode = fail, "some" = partial, never on one signal alone; in operate mode only quality signals count.
- [minor] SLP-05: Animations are useful, subtle and respect prefers-reduced-motion. Check: List animations and their purpose; test with reduced motion enabled.

## Responsive (RSP)

Adaptation to mobile, tablet and desktop.

Applies when: The project has a user interface.

Rules:

- Design mobile first, then widen; test at 360, 390, 768, 1024, 1440 and 1920 px (some layouts only break on wide screens).
- Touch targets at least 44 × 44 px; no feature available only on hover.
- Images served at the right size (srcset or the framework's image component).

Done means:

- [BLOCKER] RSP-01: No horizontal scroll or clipped content from 360 to 1440 px. Check: Screenshots at the 5 reference widths and scrollWidth check, then at every flow step (horizontal_overflow in flows.json).
- [major] RSP-02: Touch targets at least 44 × 44 px on mobile. Check: Measure buttons, icon links, checkboxes in mobile view.
- [major] RSP-03: No hover-only feature. Check: Menus, tooltips and actions reachable by touch.
- [minor] RSP-04: Layout adapted to each format, not just shrunk. Check: Navigation, tables and grids reorganised on mobile and tablet.
- [minor] RSP-05: Safe areas and on-screen keyboard handled on mobile. Check: Notch, iOS bottom bar and field hidden by keyboard tested.

## Accessibility (A11Y)

Contrast, keyboard navigation and screen readers (target WCAG 2.2 AA).

Applies when: The project has a user interface.

Rules:

- Semantic HTML first: button for actions, a for links, one h1, headings in order.
- Contrast at least 4.5:1 for text and 3:1 for components and large text.
- Everything works by keyboard, with always-visible focus and a logical order.
- Every field has a visible label; every meaningful image has alt text; every icon button has an accessible name.
- Information never relies on colour alone.

Done means:

- [BLOCKER] A11Y-01: No critical or serious axe-core violation on main pages and flow states. Check: axe-core (via Playwright) on each main page and at every step of the key tasks (flows.json). An empty screen with no violation is not enough to pass.
- [major] A11Y-02: Main flows fully doable by keyboard, visible focus. Check: Tab, Shift+Tab, Enter, Space, Esc on each key task, in the filled state (test data loaded); modals trap and restore focus.
- [major] A11Y-03: Compliant contrast (4.5:1 text, 3:1 components). Check: Measure on colour tokens and rendered pages, in every theme.
- [major] A11Y-04: Labels, text alternatives and accessible names present. Check: Fields without labels, images without alt, icon buttons without aria-label.
- [minor] A11Y-05: Structure readable by screen reader (headings, landmarks, announcements). Check: VoiceOver or NVDA test; errors and notifications announced (aria-live).
- [minor] A11Y-06: 200% zoom without loss of content, page language declared. Check: Browser zoom at 200%; lang attribute on html.

## Compatibility (CMP)

Browsers and devices.

Applies when: The project has a user interface.

Rules:

- Declare target browsers (browserslist) and stick to them for CSS and JavaScript.
- Check support for a recent API before using it, with a fallback if needed.
- Test iOS Safari as well as Chrome: most mobile bugs show up there.

Done means:

- [major] CMP-01: Main flows tested on Chromium, Firefox and WebKit. Check: Playwright tests on all three engines.
- [major] CMP-02: Target browsers declared and respected. Check: browserslist present; no unsupported API without fallback.
- [minor] CMP-03: Tested on at least one real iPhone and one real Android device. Check: Main flow run by hand on a real device.
- [minor] CMP-04: Works without extensions and with an ad blocker. Check: Blocked third-party scripts do not break the app.

## Craft (CRF)

The details that separate a cared-for product from a first draft: typography, states, motion, images, waiting, side pages.

Applies when: The project has a user interface.

Rules:

- Typography: text-wrap: balance on headings, tabular figures in columns and counters, real characters (’ “ ” … and non-breaking spaces), tracked capitals, 4 weights at most.
- Soft shadows in two layers or more, one light direction, tinted by the background; an elevation scale, not one shadow per component.
- Concentric radii: inner radius = outer radius − padding.
- Every control has its states: hover, visible keyboard focus, pressed, disabled, loading. Hover and focus contrast more than rest.
- Motion: 100 to 300 ms on the interface, ease-out, transform and opacity only, never transition: all; no animation on a keyboard or very frequent action.
- Waiting: nothing under 1 second; indicator delayed by 150 to 300 ms then kept at least 300 ms; skeleton matching the layout for a page; progress bar beyond 10 seconds.
- Optimistic update when success is likely, with rollback; undo rather than confirm for what is reversible.
- Dark theme: its own elevation model (surfaces get lighter as they rise), color-scheme: dark declared, never a plain inversion.
- State in the address (filters, tabs, page, open panel): sharing, reloading and going back work.
- Take every key screen through hard conditions before calling it done: slow network, failing server, texts three times longer, 320 px, dark scheme, keyboard only (`sw stress`), then the empty state and very long data by hand.
- Care for what surrounds the page: site icon, share image, 404 and error pages in the product's voice, tab title that follows the context.

Done means:

- [BLOCKER] CRF-01: No visible or obstructive finish defect on the key screens. Check: craft.json on the main pages and work screens: no failed "must" (keyboard focus, stretched or blurry images, fields under 16 px on phone, blocked zoom, layout shift, unaligned figures, site icon, 404 status).
- [major] CRF-02: Typographic, surface and motion finish kept. Check: craft.json: each failed "should" is fixed or justified by a choice written in DESIGN.md (balanced headings, typographic characters, shadows, nested radii, hover, durations, icons).
- [major] CRF-03: Every control has all its states. Check: Buttons, fields, links, tabs of the key screens: hover, focus, pressed, disabled and loading exist and differ; a loading button keeps its label.
- [BLOCKER] CRF-10: Every key screen holds in hard conditions. Check: stress.json on every key screen: no failed "must" (blank screen while loading or when the server does not answer, uncaught error, overflow with texts three times longer, sideways scrolling at 320 px, trapped keyboard focus). Screenshots read.
- [major] CRF-11: Waiting and error states present on every key screen. Check: stress.json: each failed "should" is fixed or justified (waiting indicator, error message with a way to retry, text cut without an ellipsis, content reached by keyboard). The empty state of each list is checked by hand.
- [major] CRF-04: Waiting handled according to its length. Check: Throttled network on a key task: no indicator flashing under 300 ms, faithful skeleton for pages, progress beyond 10 seconds, no blank page.
- [major] CRF-05: Undo for what is reversible, confirmation for the rest. Check: Delete, archive, move: undo offered for at least 5 seconds. Irreversible action: confirmation naming what will be lost.
- [major] CRF-06: The address reflects the screen's state. Check: Apply a filter, change tab or page, then reload and go back: same state, same scroll position.
- [major] CRF-07: Dark theme built, not inverted (only if: dark_mode). Check: Surfaces get lighter with elevation; hairlines in low-opacity white; no black shadow on a black background; native controls and scrollbars dark.
- [minor] CRF-08: Keyboard first on work screens. Check: Enter submits the form; Escape closes; lists move with arrow keys; shortcuts are shown; a multi-screen app has a search or a command palette.
- [minor] CRF-09: Emails and error pages look like the product. Check: 404 and 500 pages, service emails: same voice, colours and typography as the app, and an action to continue.

## Identity and true content (BRD)

An identity of the product's own, real and checkable content, licensed resources.

Applies when: The project has a user interface.

Rules:

- Draw colour, type and imagery from the product's subject and audience, not from the category's fashion.
- Avoid the three reflex palettes: purple-indigo, cream and terracotta, near-black and acid green.
- Two typefaces at most, plus a monospace if needed; not Inter or Geist as the only face; record name, foundry, licence and source of each font.
- One icon set, one stroke width tuned to the size; draw the few icons of the product's own objects; never a glyph of the icon set as the logo.
- Imagery, in order of preference: the real product (screenshots, components), diagrams made for the page, own photos, archive images with a consistent treatment, nothing. No kit illustrations and no generated image containing text, an interface or people.
- For the screens that carry the product, build several versions that really differ, have them compared blind and let the user choose (design-variants skill); lean on the reference bank of the site type (`sw bank`), to learn and never to copy.
- Every number, quote, customer logo or badge shown comes from a fact supplied by the user; otherwise the block does not exist.
- Copy: say what the product does and for whom, in customers' words; button label = verb + object; error = what happened + how to fix it.

Done means:

- [BLOCKER] BRD-01: No invented testimonial, figure, customer logo or badge. Check: Every quote, number ("10,000 teams", "99.9%"), logo and badge on public pages traces to a source supplied by the user. The run's facts.json (`sw facts` on each public page): no claim left untraced to .quality/facts.json; read the list, the tool finds claims by pattern. No source: fail.
- [major] BRD-02: Visual direction drawn from the product, written and followed. Check: DESIGN.md says where colour, type and imagery come from, and what the product refuses; the screens comply; no unjustified reflex palette. When references are measured (.quality/references.json), each gap reported by `sw gap` is closed or justified.
- [major] BRD-07: The screens that carry the product were chosen among several versions. Check: For the public home page and the main work screen: a .quality/variants/ folder with at least two versions compared, the jury's votes and the user's choice; or a written reason for not doing it.
- [major] BRD-03: Typeface chosen, licence recorded. Check: Two families at most (plus a monospace); the text face has real italics and tabular figures; name, foundry, licence and source recorded; fonts hosted by the project.
- [major] BRD-04: One icon set, adjusted, and a logo that does not come from it. Check: One set, one stroke width per size; the product's own objects have their icon; the logo is not a glyph of the set; site icon, share image and avatar derive from the same drawing.
- [major] BRD-05: Real and consistent imagery. Check: Pages show the real product; no kit illustration, no generated image with text, an interface or people; one treatment for all; source and licence recorded.
- [major] BRD-06: Specific copy, in a consistent voice. Check: The main headline says what the product does and for whom; buttons as verb + object; errors with their fix; the same word for the same thing everywhere; no run of three blocks of identical length without a reason.
